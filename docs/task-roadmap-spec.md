# タスクロードマップ仕様

## 目的

タスクの完了までに必要な具体的な作業をAIが提示し、チームメンバーが実際の進行に合わせて編集・完了できるようにする。

## 生成

- タスク作成後に非同期でロードマップを生成する。
- タスク作成自体はロードマップ生成の成功を待たずに成立する。
- 生成状態は `pending / generating / ready / failed` とする。
- AIの応答待機中はDB接続を保持しない。
- 同一タスクが `generating` の間は、新しい生成処理を重複して開始しない。
- 生成開始から2分を超えた `generating` は中断済みとみなし、次の状態確認時に再試行する。
- 議事録から複数タスクを作成した場合、ロードマップは1件ずつ生成する。
- バックエンドの各実行環境では、ロードマップのAI生成を同時に2件までに制限する。
- 失敗時は既存のタスクとロードマップを維持し、ユーザーが再試行できる。
- AIは概要文と、タスクの複雑さに応じた1〜8件の具体的なステップを生成する。
- GeminiのJSONスキーマで出力形式を強制し、AI呼び出しは1回だけ行う。
- AIは新しいロードマップ案だけを生成し、既存ステップの保護と統合はコードで行う。
- AIの応答が利用できない場合は、タスク本文から1件の代替ステップを作成する。
- AIはステップの進捗を判断しない。新規ステップは、タスクが完了済みの場合を除き `todo` とする。

## ユーザー編集

- チームメンバーはステップを追加・編集・並べ替え・削除できる。
- 手動変更は1タスク分のロードマップ下書きとして保持し、タスク情報と同じ「変更を保存」で一括保存する。
- 一括保存では、ステップの追加・編集・並べ替え・論理削除・状態変更を同一トランザクションで反映する。
- 保存時はロードマップのバージョンを照合し、別の操作による更新との競合を検出する。
- ユーザー追加ステップとユーザー編集済みステップは、AI再生成で上書きまたは削除しない。
- ユーザーが並べ替えた既存順序を維持し、新規AIステップは末尾へ追加する。
- 削除は論理削除とし、再生成で同じステップを復活させない。
- 概要文は初期リリースではAI生成の読み取り専用とする。

## 再生成

- タスクのタイトル、本文、関連議事録が更新されたら再生成する。
- 既存ステップのステータスは維持し、新規AIステップだけを `todo` にする。
- 未編集かつ未着手のAIステップだけ、AIによる更新・削除を許可する。
- 重複した生成要求では、最新入力に対する生成結果だけを採用する。
- 古い生成結果は生成ごとの識別子を照合し、再試行後のロードマップへ反映しない。
- 完了済みタスクは自動再生成せず、関連情報の更新ありとして表示する。

## 完了と再オープン

- タスクを完了すると、全ステップを完了にする。
- 全ステップが完了すると、タスクを完了にする。
- 完了済みタスクを再オープンするには、次のいずれかを明示的に行う。
  - 既存ステップを未完了へ戻す。
  - 新しいステップを追加する。
  - 「再オープンして再生成」を実行する。
- 再生成後に未完了ステップがなければ、タスクを再び完了にする。

## 完成条件

- タスク作成後に実データのロードマップが生成される。
- 生成中、失敗、再試行の状態が画面に表示される。
- ステップ編集と並べ替えが永続化される。
- 再生成後もユーザー編集と進捗が維持される。
- タスクとステップの完了が双方向に同期する。
- 完了済みタスクの更新通知と明示的な再オープンが動作する。
